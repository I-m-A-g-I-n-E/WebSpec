    ROADMAP-C¶

    Index of every TODO(C) item — multi-tenant (tier C) work that is located, not built. Tier C is the eventual public, many-user WebSpec service; tier B (what ships today) is the self-hostable single-operator gateway. Every row below is Proposed (C): named and mapped to a spec section, but not implemented. See the status matrix for the Implemented-vs-Proposed summary, and the design doc itself — docs/superpowers/specs/2026-07-11-webspec-roadmap-design.md — for full detail (this file mirrors its §8 summary index).

    Item Spec section
    Pluggable SecretBackend (1Password Connect, other password managers, HashiCorp Vault) — B ships only the op-CLI backend §3.1 Auth model
    Per-user / asymmetric guard keys (per-user vault items, or client-holds-private-key / gateway-holds-public-key Ed25519) so tenants can't sign for each other §3.1 Auth model
    1Password-issued bearer validated per-request (a "real" server-side session), instead of a shared symmetric secret §3.1 Auth model
    Widen guard HMAC tag to ≥16 bytes, or move to Ed25519 signatures (current 4-byte definer tag is a tamper-evidence checksum, not the auth boundary — the guard HMAC's security rests on nonce + key secrecy) §3.2 Hardening pass, item 5
    Multi-vector semantic search (canonical/predicate/object indices), per-user preference & history boosts, negative-example repulsion, query expansion §5.1 B1 — Semantic resolver — described today in docs/discovery/*
    Provider billing/quota/liveness enrichment ("does this API key still have credit / an active account") — no generic shortcut, one adapter per provider §5.2 B2 — Keychain graph & secrets catalog
    OAuth/JWT identity, multi-tenant config & isolation, format suffixes, REST collection hierarchy — the aspirational docs/url-grammar/* and docs/auth/* surface, not needed for B §8 summary index
    De-duplicate docs/ vs wiki/ — they are near-identical hand-maintained mirrors; make wiki/ generated from docs/ (or drop it) so there is a single source of truth. Not done in this task — wiki/ is left untouched here and tracked as this follow-up. §6, item 5 ("§6.5")

    Method profiles (from method-profiles.md §16)¶

    • Canonical path word order ("what it is, what it does, what's done to"); today the path is the MCP tool name
    • Proof of read: If-Match + gateway-issued ETag / signed read receipt on PUT/PATCH/DELETE
    • Argument validation against each tool's inputSchema (with query-string type coercion for GET)
    • Wider tags (guard, bookend, clearance are 32-bit) or Ed25519 request signatures
    • Provenance v2: bind links to the request fingerprint + nonce before enforcing them
    • Persistent, operator-approved contract pins (methods.py ContractPins)
    • Off-host, fail-closed audit at level ≥ 3 (audit.py)
    • Out-of-band approval device (phone push showing the summary) for level 4
    • Edge support for qualifier labels: Caddy host blocks + per-destination wildcard certificates (hostgrammar.py)

    Registry (from the registry plan)¶

    • EmbeddingMatcher / multi-vector semantic search (matcher.py) — spec §5.1
    • recency & preference boosts, per-user history (resolver.py) — spec §5.1
    • balance/quota/liveness enrichment per provider (keychain.py) — spec §5.2
    • account→service linking by URL/title (keychain.py) — spec §5.2
    • noun-containment poset ordering (graph.py) — spec §5.2
    • public exposure of the registry service via ported guard middleware (app.py) — spec §3.4
    • ~~Guard-aware catalog harvesting~~ — implemented (catalog.py http_fetch_tools(..., guard_key=): nonce+HMAC retry on 401/403, reusing webspec.guard.compute_guard_hmac). Requires the registry to have WEBSPEC_GUARD_KEY; degrades to unauthenticated when absent.
    • _cached_default_catalog has no lock (concurrent cache-miss requests can each re-harvest — thundering herd), and _default_catalog does blocking urllib inside async endpoints (blocks the event loop); move harvest off-loop / add a single-flight lock (__main__.py)
